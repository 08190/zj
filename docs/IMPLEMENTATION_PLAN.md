# 实现计划与验收门槛

当前进度以 VALIDATION.md 和 DESIGN_AUDIT.md 为准：单轮、多轮工程和 OpenAI 真实联调均已完成；专家签署、真实现场标签评估和最终公网部署仍待完成。下文保留阶段设计背景，历史“待配置”描述不代表当前状态。

## 第一阶段：本地确定性骨架（本次完成）

交付本地页面、接口、命令行、FaultReport、工单 JSON 草稿、完整原始知识快照和领域 SKILL。
优先固定三种现场行为：低温候选分析、高风险停机、缺失压力读数追问。
验收：全部报警可检索；原因和步骤存在来源；危险状态覆盖普通排查；历史不进入已确认根因；无资料时升级；知识快照改变即停止。

## 第二阶段：市售模型与真正的语义 RAG

**当前进度（MVP 0.2）：工程实现与离线测试已完成，真实服务联调待配置。** 已交付结构化测量与冲突检查、H02/H03 数值比较、17 个可追溯文档块、模块过滤与向量阈值、OpenAI 兼容模型审阅和运行时验证。复杂时间线与测点解释仍未实现；不能宣称第二阶段全部验收完成。具体配置见 MODEL_SETUP.md。

1. 选定现场可访问的模型服务，密钥放环境变量；新增独立解析器与生成器，不改变确定性安全检查与报警字典。
2. 用结构化输入解析设备、报警、读数、单位、时间、否定范围和不确定性。原始文本保留，解析结果不能把未提及当作否定。
3. 将逐页知识拆为报警、规则、案例、维修单元，每个 chunk 保留 source_id 和页码；原始内容是数据，不作为模型指令。
4. 精确报警优先，同时按模块检索历史与维修；语义召回后使用元数据过滤和相似度阈值。离线回退必须在报告中明示。
5. 对 H02 的 165°C/128°C/0A 与 H03 的 0.64/0.41MPa 逐项比较相同、不同、未知；仅调整候选顺序，不推断已确认根因。
6. 引入强类型 schema 及运行时验证：每条事实来源、cause 和 step 的引用、允许状态和必填字段；模型失败回退确定性报告。
7. 加入模型生成后的第二道安全审查；不允许模型修改安全规则、跳过授权边界或输出无证据动作。

验收：真实模型端到端调用成功；至少 30 条人工标注输入覆盖同义词、否定、混合报警、单位和矛盾；危险漏放为 0；无依据诊断为 0；模型或网络失败仍能输出安全降级结果。单测模拟接口不能替代真实模型联调。

## 第三阶段：现场验收加强

增加明确的安全确认输入、结构化读数表单和诊断会话，按缺失字段追问。区分观察、隔离、检查、维修、复机五类动作与授权角色。
检查多条现场读数冲突、型号不匹配和报警与温度矛盾，依据 SAFE-05 阻断。人工审核知识 JSON 与原 PDF 表格的一致性并签署版本。
增加持久化报告 ID、时间、模型版本、知识版本、检索排名、成本和审计事件；数据留存与权限由部署方确定。
验收：三组黄金案例重复运行结果稳定；两个以上回合补充信息不会丢失危险征兆；错误输入和异常服务可解释；页面在目标电脑正常运行。

## 第四阶段：飞书多维表格

先定义字段映射：工单ID、设备、故障描述、风险状态、专家类型、待补信息、证据来源、知识版本、人工确认根因、工单状态、复机结果。
使用独立适配器将草稿映射为表格记录，诊断引擎不直接持有飞书凭据。提交前展示预览，人工提交；以 report_id 作为幂等键，避免重复建单。
状态建议：草稿 → 待审核 → 已派单 → 处理中 → 待复机确认 → 已关闭。专家路由与复机确认必须有人负责。
验收：测试表中写入、幂等重试、权限不足和失败重试可验证；关闭工单不能自动授权复机。当前未接通飞书，也未发送任何数据。

## 实现选择

MVP 使用标准库降低安装障碍；业务模块与页面、知识、输出结构分离。后续可将 server.py 替换为 FastAPI、models.py 替换为 Pydantic，状态流迁移 LangGraph，但保留当前测试为回归基线。
暂不引入多 Agent、实时设备控制、图片诊断或自动维修。这些能力不影响首轮故障报告验收。
