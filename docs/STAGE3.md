# 第三阶段：多轮会话与数据边界

已实现本机会话持久化、原始输入与每版报告留存、读数更正记录、稳定工单编号及递增版本、刷新恢复和完整会话导出。
普通补充保留旧读数；不同读数并存会触发冲突。确认误录时选择“更正之前的读数”，例如“实际温度140°C”，会替换该字段的有效读数但保留原文。
安全阻断或专家复核一旦触发，本会话后续输入不会自动解除。当前没有授权专家签署解除入口。新建会话不代表设备可以复机。

会话存于 runtime/sessions.sqlite3（包含现场描述，位于本机）；浏览器只保存最近会话编号。应用以单进程本地使用为范围，无用户账户和跨设备同步。
提交带请求编号与预期版本，相同请求重复发送返回原结果，旧版本更新返回冲突。单会话最多 30 轮、原始输入累计 32000 字、有效描述 8000 字。
会话期间核对知识版本；知识变化需人工核对。进程意外终止在远程请求后、数据库提交前仍可能导致重试再次调用供应商，不承诺跨崩溃计费去重。
完整会话和工单都是草稿，未发送飞书。

使用：
1. 关闭原来运行服务的命令窗口，重新双击 start-openai.cmd，在本机输入密钥，通过检查后打开 127.0.0.1:8765 并刷新。页面应显示 MVP 03。
2. 输入 A203，实际128°C；生成后补充“加热电流0A”，应保留两项读数。
3. 选择“更正之前的读数”，输入“实际温度140°C”；应更新读数并保留三轮原文。刷新仍可恢复。
4. 新建会话输入“A520，金属摩擦声”；再补充“现在没有异常”，应继续立即停机。导出完整会话查看版本记录。
