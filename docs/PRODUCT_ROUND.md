# 产品化改进轮次

本轮将现场页面从单一自由文本升级为“结构化字段 + 自由描述”。设备编号、产线/工位、报警码、发生阶段、故障时间、报告人和危险现象会被写入同一会话记录，工单同步保留现场上下文。

报告中的证据分为设备说明书、安全规则和历史候选。每个可能原因均显示证据等级和“待现场验证”，并根据当前读数分为“优先核查 / 保留候选 / 当前证据不支持”。分层只改变核查顺序，不删除原因、不确认根因；历史案例仍只能调整候选顺序。维修工单采用 `DRAFT` 生命周期起点，记录指派角色和状态历史，且始终保持 `restart_approved=false`。

信息不足时，系统从当前报警对应的说明书追问中选出一个最能区分候选原因的问题，并说明选择理由。多轮补充后，页面单独显示新增或更正的读数、诊断状态变化、原因优先级变化和已经补齐的问题，使用户能看到新证据如何改变诊断。

每份报告包含独立 `trace_id`、知识快照摘要、检索通道、模型状态、策略路径和诊断耗时。这些字段用于导出审计和后续接入 Langfuse/Phoenix，不显示在现场主界面。

证据卡片可以打开本知识快照内的原始 PDF 并定位到引用页。公网模式下 PDF 与报告使用同一访问认证。人工复核的提交、接单、退回补充和意见登记会生成工单状态投影；该投影保留自报经办人和状态历史，但始终不授予复机权限。

冻结集首次结果 `frozen_holdout_first_run_v1.json` 保持原样。本轮修复并列否定、A401 同义表达、模糊报警码和未知报警的证据路径后，另存回归结果，不改写首次记录。

验证结果：122 项自动测试通过；冻结集最新开发回归 12/12；新增测试覆盖原因分层不删减、下一问选择、安全阻断不继续追问以及多轮变化使用可读原因名称。评测脚本已改为输出 `frozen_holdout_latest.json`，不会再覆盖首次 5/12 记录。
