# MVP 0.5：本地复核流转

现在可以把具体版本的诊断交给本地复核流程，登记接单、待补信息和复核意见，导出完整复核包。本版本没有账号或专家身份核验，因此记录均标注“身份未核验”，不是授权签署；不会解除安全锁、确认根因或批准复机。

## 页面操作

1. 关闭旧服务窗口，重新双击 start-openai.cmd；页面应显示 MVP 05。若要同时验证真实模型多轮流程，使用 check-multiturn-openai.cmd，在本机输入密钥。
2. 生成诊断报告，滚动到“本地复核流转”，填写登记人和说明，点击“登记待复核”。这里只保存到本机，不会通知或发送给他人。
3. 填写说明并“登记接单”。之后可“要求补充信息”（每行一个问题），或“记录复核意见”。
4. 需要补充时，把新的现场事实填入上方诊断输入框。诊断更新后，复核包显示过期，必须重新“登记待复核”，再接单和记录意见。
5. “导出复核包”包含原始会话、对应版本报告、证据、安全要求、历次提交快照和流转事件。登记意见不会覆盖模型报告中的未确认原因。

状态：待本地复核 → 复核中 → 待补充信息 / 已登记意见。现场更新后重新提交会回到待本地复核，保留旧记录。

## 重要约束

- 姓名由填写者自报，任何本机使用者均可登记；不是权限边界、签名或可信身份。接单人字段仅用于演示流转，不提供人员责任认证。
- “已登记意见”不等于工单已关闭。系统没有批准复机、解除停机、签署或确定根因的接口。
- 复核意见不进入诊断解析。新增危险、读数等现场事实必须先提交诊断，再重新复核。原有安全要求继续有效。
- 复核绑定报告版本与完整知识摘要；现场或知识变化时不能继续按旧版处理。旧包可以导出查阅。
- 重复请求沿用请求编号；版本冲突会拒绝写入。页面在未确认提交时保留请求供刷新后重试，避免重复登记。
- 每次复核最多100个事件；备注最多2000字、问题最多10项。到达上限后导出交人工整理。
- 数据仍存本机 runtime/sessions.sqlite3，没有发送飞书，没有加密、不可篡改存储或企业权限隔离。安装包不包含运行数据库。

## 验证与下一步

99项自动检查通过，其中新增12项复核检查；页面测试覆盖完整流转、报告变更后失效、重新提交、响应丢失刷新重试、导出和390px窄屏。既有会话恢复页面回归亦通过。

本机 last-live-check.json 仍为旧单轮通过记录，未包含 multiturn 结果。新版真实多轮不能算完成。

正式专家闭环仍需企业账号、授权角色和设备负责人定义签署/复机流程。后续接飞书时先做字段预览、显式提交和失败去重；不能以“填写姓名”替代授权身份。
